Choosing a dictionary for a word game

A multiplayer word game needs one shared answer to a simple question: is this spelling in the list? Spliinter uses a general-purpose English word-list package and combines it with letter-count and round rules on the server.

The current source

Spliinter loads the word-list npm package at startup. The installed package version is 4.1.0 and its package metadata declares the MIT license. Its text file is loaded into an array for selecting words and a set for fast membership checks. The server adds three explicit entries to the loaded list; the current process reports 274,140 unique entries after that merge.

The package’s license declaration describes the package. It should not be confused with a claim that every English dictionary or word corpus has the same license or provenance. If the source list or distribution method changes, its notices and licensing should be reviewed again.

What acceptance means

A word is accepted when it passes all game checks: it is at least three letters, is not the full base word, uses only available letters without exceeding their counts, and is present in the loaded set. Spliinter does not ask a second dictionary or a human judge to approve each submission during a round.

The list is general-purpose, so it includes entries some players will not recognize. The server does not apply a separate filter that classifies an entry as a proper noun, abbreviation, regional spelling or offensive word. Membership in the loaded word set and the game rules decide acceptance. This also means a familiar spelling can be rejected if that exact form is not in the list.

Inflections and spelling variants

Plural, past-tense and other forms are not created automatically by a grammar engine. Each candidate form must have its own dictionary entry and fit the base word’s letters. A stem in the dictionary does not guarantee that its plural or -ING form is also accepted.

The game uses the entries it loaded; it does not convert between British and American spellings or normalize alternate spellings to one preferred form. If two forms are present in the list, both can be considered, subject to the other checks.

How base words are chosen

In the default configuration, base-word candidates are 9–12 letters long and filtered to avoid words that are just inflections of shorter dictionary entries. The picker also checks that a candidate can form at least 120 smaller dictionary words using the same inventory rule. If the requested game cannot be filled from random candidates, it can use the hand-picked common-word pool. The explicit BASE_WORDS=common configuration selects from that pool directly.

Choosing a base word and validating a player answer are related but separate tasks. The base-word picker favors enough possible subwords for a round; the answer validator checks one submitted word against the current base and loaded list.

Why use a broad list?

A broad shared list gives all players the same deterministic rule and avoids waiting for a human decision while the clock is running. The tradeoff is that some accepted words may be obscure. A curated competition dictionary could make the vocabulary more predictable, but it would also require a clearly chosen edition, updates and rules for disputed words.

For now, Spliinter exposes the general-purpose list’s behavior rather than claiming every accepted entry is common or universally accepted in every word game. The best report includes the exact spelling and base word so the current check can be reproduced.

Reporting an unexpected result

Email contact@spliinter.in with the candidate and base word, and say whether the server accepted or rejected it. Do not include private player submissions from someone else. The game does not currently publish a rejection leaderboard or monthly counts, so this report is a request for review rather than an item in a public statistics feed.
